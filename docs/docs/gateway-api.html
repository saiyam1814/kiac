Gateway API

One flag installs the Gateway API CRDs and Traefik with a GatewayClass and a default Gateway already accepted, so a plain kubectl apply of an HTTPRoute routes traffic with zero extra setup.

kiac create cluster --name dev --workers 2 --gateway

The same flag works on every path: kubeadm (default), --distro k3s (where k3s's own bundled Traefik ingress is disabled so kiac's Traefik owns ports 80/443), and --cni cilium --kernel full clusters.

What gets installed

PieceDetail
Gateway API CRDsv1.5.1, experimental channel, vendored from the upstream release
Traefikv3.7.6, Deployment in namespace kiac-gateway, type: LoadBalancer Service on ports 80/443
GatewayClasstraefik (controller traefik.io/gateway-controller)
Gatewaykiac in namespace kiac-gateway: HTTP listener on port 80, accepting routes from all namespaces

Why the experimental CRD channel? Traefik v3.7's Gateway provider unconditionally watches TLSRoute and BackendTLSPolicy, which the standard channel does not install; without them the GatewayClass never goes Accepted. The experimental install is a superset of the standard one, so standard resources behave identically.

--gateway requires the built-in LoadBalancer: combining it with --no-lb is an error. At the end of create, kiac prints the address:

Gateway API ready: http://192.168.64.3 (GatewayClass traefik, Gateway kiac-gateway/kiac)

Full HTTPRoute walkthrough

1. Deploy something to route to.

kubectl create deployment web --image=nginx
kubectl expose deployment web --port=80    # plain ClusterIP; the Gateway does the exposing

2. Apply an HTTPRoute. The only kiac-specific part is the parentRefs, which attach the route to the default Gateway:

cat <<'EOF' | kubectl apply -f -
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: web
spec:
  parentRefs:
    - name: kiac
      namespace: kiac-gateway
  hostnames: ["web.local"]
  rules:
    - backendRefs:
        - name: web
          port: 80
EOF

3. Check the route attached.

kubectl get httproute web
kubectl get gateway kiac -n kiac-gateway   # ADDRESS shows the LoadBalancer IP

4. Curl it. Grab the Gateway address and send the Host header the route matches on:

GW=$(kubectl get svc traefik -n kiac-gateway -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
curl -H "Host: web.local" http://$GW/
<!DOCTYPE html> ... Welcome to nginx! ...

Prefer a real hostname in the browser? Map it in /etc/hosts:

echo "$GW web.local" | sudo tee -a /etc/hosts
curl http://web.local/

Path matching, header matching, traffic splitting, and everything else in the Gateway API spec work the same way; kiac only pre-creates the Gateway so you can start at the HTTPRoute.

For a full copy-paste walkthrough, see examples/gateway-api-lab.md. It covers GatewayClass, Gateway, HTTPRoute attachment, hostname and path matches, status checks, and troubleshooting.

Operational details

  • The default Gateway accepts routes from every namespace (allowedRoutes.namespaces.from: All), so HTTPRoutes work from wherever your app lives.
  • Traefik publishes its Service's LoadBalancer address into the Gateway's status, so kubectl get gateway shows the same IP the Service has.
  • The Traefik Service shares its node IP with Grafana when --observability is also on: kiac-lb shares an IP whenever port sets are disjoint, and 80/443 vs 3000 do not overlap. The Traefik pod is pinned to the kiac.io/lb-primary node so delivery stays pod-local; see Networking.
  • The HTTPS listener port 443 is exposed on the Service, but the default Gateway defines only the HTTP listener; add your own listener plus certificates for TLS.
  • If the gateway install fails, kiac logs it and keeps the cluster running rather than tearing it down.
  • Enable via config file instead of the flag: addons.gateway: true. See Config file.
