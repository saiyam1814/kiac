Native Apple GPU service

Run fixed Metal compute and native llama.cpp inference on your Mac, with Kubernetes DRA controlling which Linux Pod receives a short-lived service credential. The Pod sends authenticated HTTPS requests; the Mac executes the GPU work.

Unreleased alpha This feature is implemented on main and requires a source build. It is not included in v0.12.0 or its Homebrew package. It adds a host service alongside the existing Venus/Vulkan GPU beta; it does not expose a Metal or CUDA device inside Linux containers.

How the native path works

Linux Pod in an Apple/container node
  → DRA lease credentials mounted read-only by CDI
  → HTTPS with the Mac service's private CA
  → Kiac host broker on macOS
  → fixed Metal compute / native llama.cpp Metal inference
  → Apple GPU

The ordinary Kubernetes nodes keep using Apple/container. You do not create --gpu-workers for this path. One explicitly selected node runs the separate metal.kiac.dev DRA driver. Its DeviceClass selects one exclusive host-service device, rather than publishing a copy of the Mac GPU on every worker.

On preparation, the driver verifies the allocated ResourceClaim and obtains a short-lived lease from the broker. CDI mounts /var/run/kiac-metal read-only into the consuming container and sets KIAC_METAL_CREDENTIALS. That directory contains only the lease credential and public CA certificate. The host admin token is mounted only into the DRA driver, never the consumer.

Both paths share the Mac's physical GPU with other applications. The native lease controls Kiac's host service, not every process on macOS. It provides neither a GPU utilization percentage nor a physical VRAM partition. Native model memory and execution remain outside the Pod's Linux resource limits and isolation boundary.

Requirements and source build

  • An Apple silicon Mac with an ordinary Apple/container cluster. The completed profile below used macOS 27.0.1 and Apple/container 1.7.1.
  • Go matching the repository's toolchain, make, kubectl, and Xcode command line tools with xcrun swiftc. Kiac compiles its fixed Metal helper locally.
  • Kubernetes 1.36 or later for DRA; the walkthrough uses the tested K3s 1.37 profile.
  • For inference, an already installed Metal-enabled llama-server executable and an existing local GGUF model. Kiac does not download a model or install llama.cpp for this service.
git clone https://github.com/saiyam1814/kiac
cd kiac
make build
./bin/kiac gpu native --help
xcrun swiftc --version

Use ./bin/kiac throughout this walkthrough so an older Homebrew binary does not receive commands it does not implement.

1. Create an ordinary cluster

./bin/kiac create cluster --name native-lab --distro k3s \
  --k8s-version 1.37 --workers 1 --cpus 2 --memory 2G

kubectl --context kiac-native-lab get nodes

The model runs on the host, so the worker does not need room to load it. The Python client in the example requests 64 MiB and limits its Linux container to 128 MiB; those values do not limit the model's host memory use.

2. Discover the VM gateway and start the service

The default listener, 127.0.0.1:5181, supports host-only use. Pods need an explicit private IP assigned to the Mac and reachable from the node VM. Read the worker's default route, then confirm the gateway address belongs to a Mac interface:

container exec kiac-native-lab-worker-1 ip -4 route show default
ifconfig

For example, a route through 192.168.64.1 and the same address on a Mac VM bridge indicate a candidate listener. The address and interface name vary with your network; 192.168.64.1 is an example, not a fixed Kiac setting. The service refuses wildcard, public and unassigned interface addresses.

In a terminal that will remain open, set your discovered address and existing model path:

MAC_VM_GATEWAY=192.168.64.1 # replace with your verified Mac VM-network IP
MODEL_GGUF=/absolute/path/to/your/model.gguf

./bin/kiac gpu native serve --listen "${MAC_VM_GATEWAY}:5181" \
  --model "$MODEL_GGUF" --server-binary llama-server

Omit both --model and --server-binary to enable only inventory and fixed compute. Inference requires a compatible local GGUF file no larger than 16 GiB. Startup requires detected Metal and full model-layer offload; partial or zero-layer offload is rejected. Use --startup-timeout 5m if a larger model needs longer to load.

The foreground process owns the model server and reaps its process group on shutdown. It uses a private CA and admin credential under ~/.kiac/native-gpu. Set the persistent --state-dir flag consistently on all commands if you choose a different private directory.

3. Check the host before attaching Kubernetes

In another terminal, from the same checkout:

./bin/kiac gpu native status
./bin/kiac gpu native self-test --count 65536
./bin/kiac gpu native chat --prompt "Name one benefit of local Kubernetes." \
  --max-tokens 16
./bin/kiac gpu native chat --prompt "Explain Kubernetes in one sentence." \
  --max-tokens 32 --stream

status checks live engine readiness. Host self-test and chat acquire a temporary exclusive lease and release it when the command finishes. They cannot borrow a lease already held by a Kubernetes claim. The self-test verifies every result from a fixed vector-add kernel, rather than only reporting a GPU name.

Chat accepts text messages through an OpenAI-compatible /v1/chat/completions route with the model alias kiac-native. This alpha uses a 2,048-token context, one concurrent operation and at most 512 generated tokens per request. Streaming uses server-sent events; the CLI requires a terminal [DONE] event.

4. Attach one node through DRA

./bin/kiac gpu native install --name native-lab --node worker-1

kubectl --context kiac-native-lab get deviceclass metal.kiac.dev
kubectl --context kiac-native-lab get resourceslices
kubectl --context kiac-native-lab -n kiac-native-gpu get pods

Installation selects a running node owned by this cluster and waits for a healthy native device published by its current driver Pod. Only that node can satisfy the native DeviceClass. Changing the selected node requires removing native consumers and claims, uninstalling, and installing again.

The default lease lifetime is 120 seconds. The driver periodically verifies the live claim and its allocation before renewal. Deleted, changed or unverifiable claims are not renewed. Broker unavailability blocks new preparation; Kubernetes API failure prevents unverified renewal. Unpreparing a claim revokes its lease.

5. Run native compute and inference from a Linux Pod

kubectl --context kiac-native-lab apply -f examples/gpu-native-inference.yaml
kubectl --context kiac-native-lab wait \
  --for=jsonpath='{.status.phase}'=Succeeded \
  pod/kiac-native-inference --timeout=5m
kubectl --context kiac-native-lab logs kiac-native-inference

This example requires the model-enabled service from step 2. The digest-pinned Python example runs as UID 1000 with a read-only root filesystem, all Linux capabilities dropped and no Kubernetes service-account token. It requests the metal.kiac.dev claim, reloads the mounted credential before every request, disables proxies and redirects, verifies the private CA, and checks both 65,536 Metal results and a bounded chat completion. It never prints the token.

The program prints selected verified fields such as device name, verified element count, error, generated token count and response text. Model output quality is not a GPU correctness test. If the Pod fails, inspect kubectl --context kiac-native-lab describe pod kiac-native-inference and its logs. This one-shot restartPolicy: Never example must be recreated after worker loss or a failed request; it does not rerun when the service or VM recovers. The VM recovery validation below used a separate restartable consumer.

Applications must reopen KIAC_METAL_CREDENTIALS for each operation. The read-only directory mount lets the driver replace the file atomically when a lease is renewed or rotated. Do not copy a token into an environment variable or cache it for the Pod's entire lifetime.

Completed alpha validation

The following results were recorded on an Apple M1 Max with macOS 27.0.1, Apple/container 1.7.1, an ordinary K3s 1.37 cluster and Linux kernel 6.18.35. The test cluster used four vCPUs and 4 GiB per VM; model memory remained on the host. They establish this local acceptance profile, not support across all Apple hardware or production environments.

Broker restart deliberately invalidates prior leases. Requests fail closed until the driver rechecks the claim and publishes a new credential, typically around the next renewal at the default interval of about 40 seconds. Clients that need recovery should reread credentials and retry transient failures within their own bounded deadline. Host sleep/wake has not been validated.

6. Remove consumers, then uninstall

kubectl --context kiac-native-lab delete -f examples/gpu-native-inference.yaml
./bin/kiac gpu native uninstall --name native-lab

Delete both the Pod and its ResourceClaim: a retained claim can continue reserving the exclusive allocation. Uninstall refuses allocated native claims, stops the renewing driver, removes its verified node-owned ResourceSlices, rechecks claims, and runs a node-local cleanup Job to revoke saved leases and remove native CDI credentials. A failed revocation keeps the cleanup checkpoint for retry; restore the host service and retry uninstall.

Keep the host service running through uninstall so it can confirm revocation. Then press Ctrl-C in its terminal. This removes the native integration without changing the separate Venus driver or deleting your local model. Delete the ordinary cluster only when you are finished with it:

./bin/kiac delete cluster --name native-lab
