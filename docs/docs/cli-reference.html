Core concepts

CLI reference

Every command and flag, straight from the source. kiac <command> --help shows the same information in your terminal.

create cluster, delete cluster, get clusters, and get nodes reject extra positional arguments. Use --name on commands that select a cluster, for example kiac delete cluster --name dev; a positional name is not a substitute for that flag.

kiac create cluster

Create a Kubernetes cluster of lightweight-VM nodes.

kiac create cluster
kiac create cluster --name dev --workers 2
kiac create cluster --memory 8G --cpus 4
kiac create cluster --distro k3s --workers 1
kiac create cluster --cni cilium --kernel full
kiac create cluster --cni flannel --kernel full
kiac create cluster --distro k3s --workers 1 --gpu-workers 1 --gpu-resource-driver dra --memory 4G
kiac create cluster --mount type=bind,source="$PWD",target=/workspace,readonly
kiac create cluster --config cluster.yaml
FlagDefaultDescription
--configcluster config YAML (see Config file); flags set explicitly on the command line override file values
--namedevcluster name (lowercase letters, digits, dashes)
--workers0number of worker nodes (control plane is untainted when 0)
--gpu-workers0real Apple GPU workers (beta); a positive value runs the complete cluster topology on krunkit while only -gpu-N nodes publish GPU inventory
--gpu-imagefedora-44verified GPU VM base-image alias, or a local raw disk path
--gpu-disk-size20Gpersistent disk size for every krunkit-backed node in a GPU cluster
--gpu-resource-driverdevice-plugindevice-plugin, or dra on Kubernetes 1.36+; see Apple GPU
--k8s-versiondistro latestKubernetes version: kubeadm defaults to 1.37 (1.32-1.37 pinned); k3s defaults to 1.37 (1.32-1.37 pinned). Versions 1.32 and 1.33 are retained for compatibility but are upstream end-of-life
--distrokubeadmKubernetes distribution per node VM: kubeadm (kindest/node), or k3s (rancher/k3s: sqlite datastore, bundled local-path storage and metrics-server; kiac-lb handles LoadBalancers). See k3s distro
--imagenode image (overrides --k8s-version)
--cnikindnetpod network: kindnet, cilium, flannel, or none (bring your own). On ordinary kubeadm clusters Cilium and Flannel need --kernel full; Flannel (upstream v0.28.9 embedded, VXLAN backend) needs no host CLI and is not available on GPU clusters; kubeadm GPU clusters use krunkit's kernel and need only the host cilium CLI. Ordinary k3s uses kindnet and GPU k3s uses bundled Flannel; both ignore this flag
--kernelcustom node kernel: full (downloads the published kiac kernel with VXLAN/eBPF/br_netfilter, cached in ~/.kiac/kernels/) or a path to an arm64 boot Image. See Cilium & the full kernel
--dnsruntime defaultnameserver IPs for the node VMs, repeatable up to 3 (resolv.conf's own limit): --dns 1.1.1.1 --dns 8.8.8.8. Given, it replaces the runtime's default resolv.conf entirely rather than adding to it (see Troubleshooting)
--ip-familyipv4ipv4, dual, or ipv6. Non-IPv4 ordinary clusters select the full kernel; GPU clusters currently require IPv4
--mountbind a host directory into every node VM; repeat type=bind,source=/host/path,target=/node/path[,readonly]. Explicit CLI mounts replace config-file mounts
-p, --publishrepeatable [host-ip:]host-port:container-port[/protocol] forwards to the control-plane VM only. Omitted host IP binds all IPv4 interfaces; use 127.0.0.1 for loopback. Ordinary apple/container clusters only; does not add API-server certificate SANs
--registry-carepeatable HOST[:PORT]=PEM_FILE; trust a registry CA for workload image pulls on every node. See registry trust
--virtualizationfalsepass apple/container's --virtualization to every node VM, exposing nested virtualization (for example /dev/kvm) inside the nodes. Needs an M3 or newer Mac on macOS 15+; KIAC checks the host's native capability before downloading create assets and fails if support is unavailable or cannot be verified. Ordinary clusters also need --kernel full: apple/container's default kernel has no KVM, so without it nodes boot without /dev/kvm and kiac prints a warning. On GPU clusters every krunkit node starts with krunkit's --nested instead, which needs a krunkit that supports it; the setting is kept across start node and resume, and host support is checked again before a stopped krunkit node boots
--k3s-controlplane-arg, --k3s-worker-argrepeatable argv tokens for ordinary K3s control-plane and worker nodes. Use --k3s-controlplane-arg=--tls-san followed by --k3s-controlplane-arg=api.dev.test. KIAC-managed flags are rejected; other conflicting values can still break the cluster. Not supported on kubeadm or GPU clusters
--cpus4vCPUs per node VM
--memory2Gmemory per worker VM (idle workers use a few hundred MB)
--cp-memory4Gmemory for the control-plane VM (etcd, apiserver, and on single-node clusters every addon)
--no-metricsfalseskip installing metrics-server
--no-storagefalseskip installing the local-path default StorageClass
--no-lbfalseskip installing kiac-lb (type: LoadBalancer support)
--no-edge-proxyfalseskip the node-local edge proxy that fixes large TCP uploads through NodePorts and LoadBalancers
--observabilityfalseinstall Prometheus + Grafana + node-exporter; Grafana uses a LoadBalancer IP or ClusterIP with --no-lb
--gatewayfalseinstall Gateway API CRDs + Traefik with a ready-to-use GatewayClass and Gateway
--wait5mpositive timeout for each cluster readiness step, including CNI installation; zero and negative values are rejected. Passed to Cilium as --wait-duration and used as Flannel's rollout status --timeout

Version resolution: a minor like 1.34 uses kiac's digest-pinned node image (kindest/node, or rancher/k3s with --distro k3s); an exact patch matches the pin when it is the pinned patch, otherwise falls back to the matching upstream tag unpinned. Kubeadm initializes the control plane at the version installed in the selected node image. K3s also accepts full releases such as v1.36.4+k3s1 and v1.36.4-k3s1. Explicit K3s build revisions are preserved, and a digest pin is reused only when the complete release tag matches.

--kernel is CLI-only. distro and the GPU options are also available as config file keys.

Delete a cluster's node VMs and its kubeconfig entries.

kiac delete cluster --name dev
FlagDefaultDescription
--namedevcluster name

kiac get clusters

List kiac clusters (alias: kiac get cluster). STATUS shows running nodes out of total, e.g. 3/3 running, or 0/3 stopped when the VMs are halted (typically after a reboot; kiac resume cluster brings them back).

kiac get clusters
kiac get clusters -o wide    # adds K8S-VERSION and CREATED columns
kiac get clusters -o json    # machine-readable, always a JSON array
FlagDefaultDescription
-o, --outputoutput format: wide or json

kiac get nodes

List the node VMs of one cluster (NODE, STATUS, IMAGE).

kiac get nodes --name dev
FlagDefaultDescription
--namedevcluster name

kiac stop node

Stop a node VM to test real node failure: the node goes NotReady and its pods reschedule. Accepts the short node name (worker-1, control-plane) or the full container name (kiac-dev-worker-1). Stopping the control plane of a single-node cluster is refused; on multi-node clusters it proceeds with a warning. See Node chaos.

kiac stop node worker-1
kiac stop node worker-2 --name staging
FlagDefaultDescription
--namedevcluster name

kiac start node

Start a previously stopped node VM. Idempotent: on an already-running node the boot is simply skipped. The node's IP may change across restarts; kubeadm re-registers it and kiac-lb re-points stale LoadBalancer IPs, while k3s runs the resume reconciler to update agent endpoints and host-network pods before returning. If several k3s nodes are stopped, use kiac resume cluster to recover them together. Note one known host-to-node TCP limitation for restarted VMs.

kiac start node worker-1
kiac start node worker-2 --name staging
FlagDefaultDescription
--namedevcluster name

kiac resume cluster

Boot a stopped kubeadm or k3s cluster and heal it after a host reboot. vmnet hands out fresh IPs on the next boot, so resume repairs the distro-specific state: kubeadm certificates, kubeconfigs, worker kubelets, and kube-proxy; or k3s agent endpoints, current Node addresses, and host-network pods. It also heals kiac networking helpers, rewrites the host kubeconfig, and waits for Ready nodes. Safe to re-run; a running cluster is a no-op. See Reboots & resume.

kiac resume cluster --name dev
FlagDefaultDescription
--namedevcluster name
--wait5mhow long to wait for boot, API server, and node readiness

kiac verify cluster

Run read-only health checks across the node VMs, required node services, API readiness, Kubernetes nodes and workloads, the pod network DaemonSet (kindnet, Cilium, or Flannel), DNS, storage, metrics, the edge proxy and its redirect rules, LoadBalancer assignments, optional Gateway and observability addons, and reachability from the Mac. Intentionally disabled addons report skip; required failures make the command exit nonzero.

kiac verify cluster --name dev
kiac verify cluster --name dev -o json
FlagDefaultDescription
--namedevcluster name
-o, --outputtextoutput format: text or stable-schema json
--timeout10smaximum duration of each node diagnostic command

kiac support bundle

Write a mode-0600, bounded, redacted tar.gz with the verification report, host and Apple container runtime status, safe Kubernetes listings (including the pod-network DaemonSet's pods and container logs as kubernetes/cni-<name>.txt and .log), and node system logs. Collection is read-only and excludes kubeconfigs, Kubernetes Secrets, raw container inspection, process environments, application logs, and edge-proxy credential files. Names, IPs, events, and system logs remain operational data, so review the archive before sharing it.

kiac support bundle --name dev
kiac support bundle --name dev --output /tmp/dev-support.tar.gz
FlagDefaultDescription
--namedevcluster name
-o, --outputtimestamped filearchive path; an existing file is never overwritten
--timeout10smaximum duration of each diagnostic command

kiac load image

Copy images from the apple/container local image store into the containerd instance of every node VM, so pods can run them without pushing to a registry. Build first with container build -t myapp ., and set imagePullPolicy: IfNotPresent (or Never) in your pod spec.

kiac load image myapp:dev --name dev
kiac load image api:dev web:dev --name dev    # several at once
FlagDefaultDescription
--namedevcluster name

kiac doctor

Check that this Mac can run kiac clusters: macOS version (26+ for multi-node), apple/container CLI 1.6.0+ (1.6.1 recommended; fixes pinned image digest verification), the container system service, kubectl, and Apple silicon.

kiac doctor
kiac doctor --fix
FlagDefaultDescription
--fixfalseattempt to fix failed checks (starts the container system service)

External worker commands (alpha)

kiac join worker provisions one Mac-hosted CPU worker for an existing IPv4 K3s cluster using Flannel VXLAN and an operator-managed WireGuard peer. Read the requirements and full workflow before joining; this command does not set up remote routes or register a GPU resource.

kiac join worker --name remote-lab \
  --server https://10.250.76.1:6443 \
  --token-file ./agent-token --wireguard-config ./worker.conf \
  --node-ip 10.250.76.2 --k8s-version 1.37
kiac get workers
kiac get workers -o json
kiac logs worker remote-lab
kiac stop worker remote-lab
kiac start worker remote-lab --wait 10m
kiac delete worker remote-lab
Join flagRequirement or default
--namerequired local external-worker name
--serverrequired HTTPS IPv4:PORT endpoint reachable over the tunnel
--token-filerequired owner-private full CA-pinned K3s secure token file
--wireguard-configrequired owner-private single-peer, split-route WireGuard configuration
--node-iprequired stable worker WireGuard IPv4 address
--k8s-versionrequired pinned K3s minor or exact release matching the server
--pod-cidr, --service-cidrexisting cluster CIDRs; defaults 10.42.0.0/16 and 10.43.0.0/16
--cpus, --memory, --diskdefaults 2, 2G, 20G
--waitbounded readiness wait, default 10m; also accepted by start worker

External workers have separate inventory and start with a NoSchedule taint. Cluster commands and the web console do not manage them. Stopping and deleting affect only the local VM; drain workloads and remove the remote Node with your external-cluster credentials first.

kiac gpu

Inspect and configure the optional real Apple GPU backend. See Real Apple GPU nodes for the architecture, prerequisites, and complete lab.

kiac gpu doctor
kiac gpu status --name gpu-lab
kiac gpu status --name gpu-lab -o json
kiac gpu inspect --name gpu-lab
kiac gpu bench --name gpu-lab
kiac gpu bench --name gpu-lab --skip-host -o json
kiac gpu values vllm
kiac gpu values ollama
kiac gpu values kserve
kiac gpu compat enable --name gpu-lab --namespace demo
kiac gpu compat disable --name gpu-lab --namespace demo
CommandPurpose
gpu doctorvalidate krunkit, vmnet-helper, SSH/cloud-init tools, and the Venus-capable renderer

kiac ui

Open a local console to create and manage clusters. Binds to 127.0.0.1 and opens your browser. See Dashboard.

kiac ui
kiac ui --port 0    # pick a free port
FlagDefaultDescription
--port5180port for the local console (0 picks a free one)

kiac completion

Generate a shell completion script for bash, zsh, fish, or powershell.

# zsh
kiac completion zsh > $(brew --prefix)/share/zsh/site-functions/_kiac
# start a new shell; if completions stay off, add to ~/.zshrc first:
#   autoload -U compinit; compinit

# bash (needs the bash-completion package: brew install bash-completion@2)
kiac completion bash > $(brew --prefix)/etc/bash_completion.d/kiac

# fish
kiac completion fish > ~/.config/fish/completions/kiac.fish

# try it in the current shell without installing anything
source <(kiac completion zsh)
