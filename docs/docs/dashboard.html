Day two

Dashboard (kiac ui)

A local web console for people who would rather click than type. Same engine as the CLI, literally: every mutating action shells out to the kiac binary itself, so the UI and CLI can never drift.

kiac ui                # serves on 127.0.0.1:5180 and opens your browser
kiac ui --port 0       # pick any free port

Tour

Cluster cards

Each cluster gets a card, auto-refreshed every 5 seconds, with a row per node showing:

  • Role (control-plane or worker), state, and the node VM's IP.
  • Live resource bars: CPU and memory per node, fed by your Mac's kubectl top nodes against the cluster's kiac-<name> context, so they work on every distro (kubeadm and k3s alike). Bars turn red at 85%. They appear once metrics-server has scraped (about a minute after create) and degrade gracefully to plain node state before that.
  • Stop / Start buttons per node, running the same node chaos commands as the CLI. LoadBalancer IPs re-point automatically after a restart; there is no pool state to re-sync.

Addon links

When the cluster has addons installed, chips appear on the card:

  • Open Grafana links straight to the Grafana LoadBalancer URL (port 3000).
  • Gateway shows the Traefik gateway's LoadBalancer IP.

On current k3s clusters, kiac-lb normally publishes one endpoint-local IP. For older k3s clusters that still show multiple ServiceLB IPs, the chips prefer the primary node's IP because the addon pods are pinned there.

kubectl Console drawer

Every card has a Console button that opens a kubectl drawer at the bottom of the page, already targeted at that cluster:

kubectl get pods -A            # you type what follows "kubectl"
kubectl get svc -n kiac-gateway
kubectl describe node kiac-dev-worker-1
  • Enter runs the command, ↑/↓ walk the history, Esc closes the drawer. A typed kubectl  prefix is tolerated and stripped.
  • Commands run your Mac's own kubectl against the cluster's kiac-<name> context, so the console works on every distro.
  • It is not a shell: the arguments go to the kubectl binary as an argv array, verbatim; nothing is interpolated, no pipes or redirects.
  • Each command gets a 20-second timeout (so logs -f cannot wedge the UI) and long output is truncated.

Kubeconfig download

Every card offers a standalone kiac-<name>.kubeconfig download, self-contained and pointed at the control plane's IP, handy for tools that want their own file instead of your merged ~/.kube/config.

Create form

The sidebar form covers the common knobs of kiac create cluster: name, workers, distro-specific pinned Kubernetes versions, CPUs and memory per node, CNI, and checkboxes for the kiac-lb LoadBalancer, metrics-server, local-path storage, observability, Gateway API, and the explicitly non-accelerated GPU scheduling mock. Switching distro updates both the available versions and the default. Progress streams into an activity panel showing exactly the log the terminal would print. (--kernel is a CLI-only knob for now.)

Delete

Card-level delete, with a confirmation prompt, equivalent to kiac delete cluster --name <name>.

Security model

The console hands out cluster-admin kubeconfigs, so it is deliberately hard to reach from anywhere but your own terminal and browser:

  • It binds to 127.0.0.1 only; nothing on your network can connect.
  • Requests with an unexpected Host header are rejected (blocks DNS-rebinding attacks).
  • Cross-origin requests are rejected (blocks CSRF from other pages in your browser).
  • One mutating job per cluster at a time, so a double-click can never race two creates or a stop against a delete.
