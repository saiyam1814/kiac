Dashboard (kiac ui)

A local web console for people who would rather click than type. Same engine as the CLI, literally: every mutating action shells out to the kiac binary itself, so the UI and CLI can never drift.

kiac ui                # serves on 127.0.0.1:5180 and opens your browser
kiac ui --port 0       # pick any free port

Tour

Cluster cards

Each cluster gets a card, auto-refreshed every 5 seconds, with a row per node showing:

  • Role (control-plane or worker), state, and the node VM's IP.
  • Live resource bars: CPU and memory per node, fed by kubectl top nodes inside the cluster. Bars turn red at 85%. They appear once metrics-server has scraped (about a minute after create) and degrade gracefully to plain node state before that.
  • Stop / Start buttons per node, running the same node chaos commands as the CLI, including the MetalLB IP re-sync on start.

Addon links

When the cluster has addons installed, chips appear on the card:

  • Open Grafana links straight to the Grafana LoadBalancer URL (port 3000).
  • Gateway shows the Traefik gateway's LoadBalancer IP.

Kubeconfig download

Every card offers a standalone kiac-<name>.kubeconfig download, self-contained and pointed at the control plane's IP, handy for tools that want their own file instead of your merged ~/.kube/config.

Create form

The sidebar form covers the same knobs as kiac create cluster: name, workers, Kubernetes version (the pinned 1.32-1.36 list), CPUs and memory per node, CNI, and checkboxes for MetalLB, metrics-server, local-path storage, observability, and Gateway API. Progress streams into an activity panel showing exactly the log the terminal would print.

Delete

Card-level delete, with a confirmation prompt, equivalent to kiac delete cluster --name <name>.

Security model

The console hands out cluster-admin kubeconfigs, so it is deliberately hard to reach from anywhere but your own terminal and browser:

  • It binds to 127.0.0.1 only; nothing on your network can connect.
  • Requests with an unexpected Host header are rejected (blocks DNS-rebinding attacks).
  • Cross-origin requests are rejected (blocks CSRF from other pages in your browser).
  • One mutating job per cluster at a time, so a double-click can never race two creates or a stop against a delete.
