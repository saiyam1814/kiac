Run Rancher on kiac

Install Rancher Manager on a dedicated kiac Kubernetes cluster, expose it through Gateway API, and prove the UI and management API paths.

Rancher Manager 2.14.3Stable Helm chart 2.14.3 on Kubernetes 1.34
Official docs
No Rancher license key is required This example runs the open-source Rancher Manager distribution. SUSE Rancher Prime is the separately subscribed support and enterprise offering.
Fresh validation: up, a separate verify, an idempotent second up, and cleanup passed against the released kiac v0.5.0. Rancher reported v2.14.3, its local cluster active, and one Kubernetes node through its authenticated API.

Requirements

Run the commands from a kiac checkout. Rancher 2.14.3 requires Helm 3.18 or newer; Helm 4 also works.

brew install --cask saiyam1814/tap/kiac
brew install helm jq
kiac doctor

The script checks for container, kubectl, curl, and openssl before changing anything.

Create and install

./examples/rancher.sh up

The script creates an isolated rancher-lab cluster with Kubernetes 1.34, four CPUs, 6 GiB of memory, and kiac's --gateway addon. It generates the password and certificate, installs one Rancher replica from the pinned stable chart, waits for the routes, authenticates, and waits for Rancher's local cluster to become active.

A successful run ends with output like this:

Rancher API version: v2.14.3
local cluster state: active
Kubernetes nodes through Rancher: 1
Gateway IP: 192.168.64.x
UI: https://rancher.192.168.64.x.sslip.io
username: admin
password file: ~/.kiac/labs/rancher/rancher-lab/bootstrap-password
Local certificate The example generates a self-signed certificate, so the browser warns before opening the HTTPS UI. Use a trusted certificate and hostname for a shared installation.

Verify the real user path

./examples/rancher.sh verify

This independent check covers Deployment rollout, Gateway programming, accepted HTTPRoutes, /ping, dashboard HTML, admin login, the pinned server version, local-cluster health, and node inventory.

The network checks use curl --resolve, so they do not depend on sslip.io DNS working through a corporate VPN. A browser still needs to resolve the displayed hostname.

kubectl --context kiac-rancher-lab \
  -n cattle-system get deploy,pod,svc,gateway,httproute

Why a dedicated cluster

Rancher is a cluster manager, not a small namespaced dashboard. It creates cluster roles, custom resources, controllers, webhooks, and system namespaces. Removing its Helm release alone is not equivalent to removing every object it owns.

The script therefore refuses to adopt an unrelated existing cluster. That makes ownership and cleanup unambiguous. You can import other kiac clusters from Rancher after installation, but importing them is outside this installation example.

Choose the name and credentials

KIAC_RANCHER_CLUSTER=management \
./examples/rancher.sh up

Use KIAC_RANCHER_HOSTNAME for a DNS name you control, or seed a password of at least 12 characters from a file:

RANCHER_BOOTSTRAP_PASSWORD_FILE="$HOME/.config/rancher-password" \
./examples/rancher.sh up

Clean up

./examples/rancher.sh cleanup

This deletes only the kiac cluster carrying the script's ownership marker, removes its kubeconfig context, and deletes the generated credential and TLS state. Without the marker, it leaves the cluster alone.

Scope and security

  • Rancher has broad privileges because it manages the local Kubernetes cluster.
  • Keep the Gateway address on a trusted local network and never commit the generated credential.
  • The self-signed certificate, single replica, and local storage are for development, not production.
  • Rancher is optional and adds no cost to ordinary kiac clusters.
  • This example does not replace kiac's dashboard or add Docker Engine and Compose compatibility.
