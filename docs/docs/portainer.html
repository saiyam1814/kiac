Run Portainer CE on kiac

Install Portainer Community Edition as an application inside a kiac Kubernetes cluster, expose its UI, and verify that it can manage the cluster.

Portainer Community Edition 2.39.5Helm chart 239.5.0 on Kubernetes 1.34
Official CE docs
No Portainer license key is required This example installs the open-source Community Edition image, portainer/portainer-ce. Portainer Business Edition is the edition that asks for a license key.
Fresh validation: both up and a separate verify run passed against the released kiac v0.5.0. Cleanup then removed the cluster, kubeconfig context, and generated credential state.

Requirements

Run the commands from a kiac checkout. The script checks every required executable before changing anything.

brew install --cask saiyam1814/tap/kiac
brew install helm jq
kiac doctor

It also uses container, kubectl, curl, and openssl.

Create and install

./examples/portainer.sh up

By default, the script creates an isolated, single-node kiac cluster named portainer-lab. It then creates the namespace and password, installs the pinned chart, waits for the Deployment and PVC, discovers the LoadBalancer IP, signs into the API, and idempotently registers the cluster in Portainer.

A successful run ends with output like this:

Portainer API version: 2.39.5
managed environments: 1
Kubernetes nodes through Portainer: 1
UI: https://192.168.64.x:9443
username: admin
password file: ~/.kiac/labs/portainer/portainer-lab/admin-password
Local certificate Portainer generates a self-signed certificate for this local installation, so the browser warns before opening the HTTPS UI. Keep the LoadBalancer address on a trusted local network.

Verify the real user path

./examples/portainer.sh verify

This command does not reinstall Portainer. It independently checks rollout status, the Bound PVC, the assigned LoadBalancer address, the pinned version from /api/system/status, JWT authentication, the healthy local environment, and a NodeList through Portainer's Kubernetes API proxy.

Inspect the underlying resources whenever you need the Kubernetes view:

kubectl --context kiac-portainer-lab \
  -n portainer get deploy,pod,svc,pvc

Use an existing kiac cluster

KIAC_PORTAINER_CLUSTER=dev \
KIAC_PORTAINER_USE_EXISTING=true \
./examples/portainer.sh up

The script refuses to adopt a pre-existing portainer namespace or Helm release. Ownership markers ensure cleanup removes only what the script created and never deletes an existing cluster.

To choose the password without placing it in shell history:

PORTAINER_ADMIN_PASSWORD_FILE="$HOME/.config/portainer-lab-password" \
./examples/portainer.sh up

Clean up

./examples/portainer.sh cleanup

For the default installation, this deletes the kiac cluster created by the script and its credential state. When using an existing cluster, it removes only the owned Helm release, namespace, and local password copy.

Scope and security

  • Portainer receives cluster-admin privileges because it manages this local Kubernetes environment.
  • The generated credential is local state; do not commit or share it.
  • Use a trusted certificate and external authentication for a shared deployment.
  • This Portainer installation manages Kubernetes. It does not turn apple/container into Docker Engine or add Docker Compose compatibility to macOS.
