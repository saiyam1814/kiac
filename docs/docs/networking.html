Core concepts

Networking

Every node VM gets its own IP your Mac can reach. That one fact drives most of kiac's networking design, from the CNI choice to how LoadBalancers work.

vmnet and node IPs

apple/container attaches each lightweight VM to macOS's vmnet network. Each node VM therefore gets its own IP address (typically in the 192.168.64.0/24 range) that is directly routable from your Mac:

kubectl get nodes -o wide
NAME                     STATUS   ROLES           VERSION   INTERNAL-IP
kiac-dev-control-plane   Ready    control-plane   v1.36.1   192.168.64.2
kiac-dev-worker-1        Ready    <none>          v1.36.1   192.168.64.3
kiac-dev-worker-2        Ready    <none>          v1.36.1   192.168.64.4

Consequences:

  • The API server is reached at https://<control-plane-ip>:6443; the kubeconfig points there directly.
  • NodePort Services are curl-able at any node IP, no port-mapping flags or tunnels.
  • Node IPs are assigned by vmnet and can change when a VM restarts (see Node chaos for how kiac handles that).
  • Multi-node VM-to-VM networking over vmnet needs macOS 26+.

Pods use the flat 10.244.0.0/16 pod network (the CIDR kiac passes to kubeadm init), routed between nodes by the CNI.

The kernel story, and why kindnet

Each node runs Apple's minimal, optimized Linux kernel (6.12 series). It is a monolithic build tuned for fast boot: there is no module loading, and it ships without several features that mainstream CNIs assume:

  • No br_netfilter (CONFIG_BRIDGE_NETFILTER): bridged traffic cannot be steered through iptables.
  • No VXLAN: overlay networks like Flannel's default backend cannot form.
  • No eBPF prerequisites: Cilium's datapath cannot load.

kindnet needs none of that. It ships inside the kindest/node image and uses plain L3 routes between node IPs, which is exactly what the vmnet topology provides. That makes it the default and currently the only bundled CNI:

kiac create cluster --cni kindnet   # default
kiac create cluster --cni none      # bring your own; nodes stay NotReady until you install one

Asking for --cni flannel, calico, or cilium fails fast with an explanation rather than half-installing something that cannot start. Custom node kernels (via container run --kernel) are on the roadmap and will unlock these.

Honest trade-off If your work depends on NetworkPolicy enforcement via Calico or Cilium's eBPF datapath, kiac's stock kernel cannot run it today. kindnet gives you real cross-node pod networking, not policy engines.

LoadBalancer: MetalLB on node IPs

kiac installs MetalLB (v0.16.0) by default and points it at the cluster's own node IPs. This is unusual and deliberate:

  • vmnet only delivers frames addressed to a VM's assigned IP. A classic MetalLB setup that floats extra virtual IPs would announce addresses no VM ever receives traffic for. Node IPs are the only addresses that are both host-reachable and deliverable.
  • kube-proxy programs LoadBalancer ingress IPs into iptables on every node, so a Service bound to a node IP answers on it just like a NodePort, but on the real port.

The pool layout, configured automatically at create time:

  • One IPAddressPool per worker node, each holding that node's IP as a single /32 (named kiac-ip-<node> in metallb-system).
  • On a cluster with workers, only worker IPs are pooled; the control-plane IP stays out of the pool so ports like 6443 never collide with a Service. Single-node clusters pool the control-plane IP.
  • Each pool's L2Advertisement is pinned to its owning node via a kubernetes.io/hostname selector. Without the pin, a MetalLB speaker on another node could answer ARP for a live node IP and hijack that node's traffic, API server heartbeats included.
kubectl get ipaddresspools -n metallb-system
kubectl expose deployment web --port=80 --type=LoadBalancer
kubectl get svc web    # EXTERNAL-IP is one of your worker node IPs

Because the pool is one /32 per worker, Services can share an IP when their ports do not overlap, using MetalLB's metallb.io/allow-shared-ip annotation. The built-in addons do exactly this: Grafana (port 3000) and the Traefik gateway (80/443) share one node IP on single-worker clusters.

Skip the whole stack with --no-lb if you prefer NodePorts only. Note that --gateway requires the LoadBalancer.
