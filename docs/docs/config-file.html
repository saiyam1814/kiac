Core concepts

Config file

Describe the whole cluster in one YAML file and check it into your repo, so kiac create cluster --config cluster.yaml gives everyone on the team the same cluster.

kiac create cluster --config cluster.yaml

Full example

This is examples/cluster.yaml from the repo; every key is optional:

name: dev            # cluster name: lowercase letters, digits, dashes
workers: 2           # worker node count; 0 untaints the control plane
k8sVersion: "1.36"   # Kubernetes minor ("1.36") or exact patch ("1.36.1")
# image: docker.io/kindest/node:v1.36.1   # node image, overrides k8sVersion
cni: kindnet         # pod network: kindnet, or none to bring your own
cpus: "4"            # vCPUs per node VM (quote it: YAML reads bare 4 as a number)
memory: 4G           # memory per worker VM
wait: 5m             # timeout for nodes to become Ready

# Addons are positive toggles; omitted keys keep the defaults shown.
addons:
  metrics: true          # metrics-server (kubectl top nodes/pods)
  storage: true          # local-path default StorageClass
  loadBalancer: true     # kiac-lb, Services of type LoadBalancer
  edgeProxy: true        # node-local TCP proxy for large external uploads
  observability: false   # Prometheus + Grafana + node-exporter
  gateway: false         # Gateway API CRDs + Traefik

Schema

KeyTypeDefaultMaps to flag
namestringdev--name
workersint0--workers
k8sVersionstring"1.36"--k8s-version

addons.metricsbooltrue--no-metrics (inverted)
addons.storagebooltrue--no-storage (inverted)
addons.loadBalancerbooltrue--no-lb (inverted)
addons.edgeProxybooltrue--no-edge-proxy (inverted)
addons.observabilityboolfalse--observability
addons.gatewayboolfalse--gateway

Notes on the schema:

  • Unknown keys are an error. A typo like worker: 2 fails the create instead of silently falling back to a default.
  • Addon keys are positive (storage: true) even though the flags are negative (--no-storage); kiac maps between them.
  • Quote cpus: YAML parses a bare 4 as a number, and the field is a string.
  • An empty file is valid and means "all defaults".
  • --distro and --kernel are not config file keys yet; pass them on the command line (they compose with --config for everything else).

Precedence

Three layers, most specific wins:

  1. A flag set explicitly on the command line always wins over the file.
  2. A key present in the file wins over the built-in default.
  3. Everything omitted keeps the CLI default.
# cluster.yaml says workers: 2, name: dev
kiac create cluster --config cluster.yaml --workers 3
# result: name dev (from file), workers 3 (flag overrides file)

The distinction is "explicitly set", not "different from the default": passing --workers 0 on the command line beats workers: 2 in the file.
