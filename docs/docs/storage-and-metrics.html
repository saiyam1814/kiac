Core concepts

Storage & metrics

Two things every local cluster needs on day one, installed by default and removable with a flag.

On the k3s distro --distro k3s clusters get the same two defaults from k3s's own bundles (local-path storage and metrics-server), and the same --no-storage/--no-metrics flags turn them off. Everything on this page applies to both distros.

Default StorageClass: local-path

Every cluster gets a default StorageClass backed by local-path-provisioner (the same manifest the kind project ships inside the kindest/node image). PersistentVolumeClaims bind without any setup, so StatefulSets and volumeClaimTemplates work immediately:

kubectl get storageclass
NAME                   PROVISIONER             RECLAIMPOLICY   VOLUMEBINDINGMODE
standard (default)     rancher.io/local-path   Delete          WaitForFirstConsumer

Try it:

cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: data
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 1Gi
EOF
kubectl get pvc data    # Pending until a pod uses it (WaitForFirstConsumer), then Bound

Things to know:

  • Volumes are directories on the node VM's disk. They live and die with the node: pin a workload with nodeSelector if the data must follow it, and expect data loss when a node VM is deleted.
  • Binding waits for the first consumer pod, so a lone PVC showing Pending is normal.
  • Skip installation with --no-storage (or addons.storage: false in a config file).

Host bind mounts and hostPath

Use a repeatable --mount to make an existing macOS directory visible inside every node VM:

kiac create cluster --name dev \
  --mount type=bind,source=/Users/me/project,target=/workspace,readonly \
  --mount type=bind,source=/Users/me/data,target=/data

The data path has two required layers:

macOS path
  -> Apple Container bind mount into each node VM
    -> Kubernetes hostPath
      -> pod volumeMount
volumes:
  - name: source
    hostPath:
      path: /workspace
      type: Directory
containers:
  - name: app
    volumeMounts:
      - name: source
        mountPath: /workspace
  • KIAC uses ordinary container run, not container machine, so the host's /Users directory is not shared automatically.
  • Every configured directory is mounted independently into the control plane/server and every worker/agent. A pod's hostPath is the target path inside whichever node schedules it.
  • Bind mounts expose host data to node VMs. Any workload allowed to use a writable hostPath, subject to filesystem permissions and admission policy, may modify host files; prefer readonly for source trees.
  • Concurrent writes from multiple nodes can be unsafe, especially for databases. Use node-local PVC storage or a suitable shared storage system instead.
  • Apple Container keeps mounts on the existing node container across stop/start and kiac resume cluster. The host source must still exist when the node starts.
  • Deleting a cluster removes its node VMs, not bind-mounted host data. Local-path PVC data is separate: it remains node-local and is deleted with its node VM.

metrics-server

kiac installs metrics-server v0.8.1 by default, patched with --kubelet-insecure-tls because kubeadm-issued kubelet serving certificates are self-signed in local clusters. That is the standard tweak every local distribution needs, done for you.

kubectl top nodes
NAME                     CPU(cores)   CPU(%)   MEMORY(bytes)   MEMORY(%)
kiac-dev-control-plane   269m         5%       828Mi           20%
kiac-dev-worker-1        35m          0%       288Mi           7%
kiac-dev-worker-2        52m          1%       359Mi           9%

kubectl top pods -A
  • Give it about 60 seconds after cluster creation for the first scrape; until then rows show <unknown>.
  • These are the same numbers the dashboard renders as live per-node bars.
  • Skip installation with --no-metrics (or addons.metrics: false in a config file).
Want more than kubectl top? --observability adds Prometheus, Grafana, kube-state-metrics, and node-exporter with dashboards already provisioned. See Observability.
