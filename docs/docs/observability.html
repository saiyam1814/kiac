Built-in addons

Observability

One flag installs a laptop-sized Prometheus and Grafana stack with dashboards already provisioned, on a URL you can open the moment create finishes.

kiac create cluster --name dev --workers 2 --observability

The same flag works on every path: kubeadm (default), --distro k3s, and --cni cilium --kernel full clusters all get the identical stack.

What gets installed

Everything lands in the kiac-observability namespace, from manifests embedded in the kiac binary (no Helm, no internet fetch at install time):

ComponentVersionNotes
Prometheusv3.5.0single replica, emptyDir storage, 6h retention, 30s scrape interval
Grafana12.0.2type: LoadBalancer on port 3000, anonymous Admin, dashboards provisioned
kube-state-metricsv2.16.0object-level metrics (pods, phases, restarts)
node-exporterv1.9.1DaemonSet; per-node CPU, memory, disk, network

Nothing in the stack needs kernel features beyond Apple's minimal node kernel; the exporters are /proc and /sys readers, no eBPF, no modules.

At the end of create, kiac prints the URL:

Grafana: http://192.168.64.3:3000 (anonymous admin, local-only)

Find it again any time:

kubectl get svc grafana -n kiac-observability
# open http://<EXTERNAL-IP>:3000
Anonymous admin, on purpose Grafana runs with anonymous Admin access and basic auth disabled. kiac clusters are local-only dev tools reachable just from your Mac, so a login screen would only get in the way. Do not reuse these manifests anywhere routable.

The provisioned dashboards

Two dashboards are provisioned from ConfigMaps, refreshed every 30s, wired to the bundled Prometheus datasource:

Cluster Overview

  • Stat row: node count, running pods, pods not running, container restarts over the last hour.
  • Time series: node CPU usage, node memory usage, pods by phase, container restarts by pod.

Nodes

  • Per-node CPU usage, memory used, load average (1m), filesystem usage, network throughput (rx/tx), and pods per node.

Both are great companions to node chaos: stop a worker and watch its lines flatline while pods pile onto the survivors.

Adding your own scrape targets

Prometheus runs a pods discovery job that scrapes any pod carrying the standard annotations. Annotate your pod template and you are in, no config reload needed:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 1
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
      annotations:
        prometheus.io/scrape: "true"   # required: opt this pod in
        prometheus.io/port: "8080"     # port serving metrics
        prometheus.io/path: "/metrics" # optional; /metrics is the default
    spec:
      containers:
        - name: myapp
          image: myapp:dev
          ports:
            - containerPort: 8080

Scraped series arrive with namespace and pod labels attached. The other preconfigured jobs are node-exporter, kube-state-metrics, kubelet, and cadvisor (container-level CPU/memory).

For a full copy-paste walkthrough, see examples/observability-lab.md. It creates the addon, deploys the sample exporter app, generates traffic, and queries both Prometheus and Grafana.

Prometheus itself is ClusterIP-only, reachable in-cluster at prometheus.kiac-observability.svc:9090. To poke at it from your Mac:

kubectl port-forward -n kiac-observability svc/prometheus 9090:9090
# open http://localhost:9090

Operational details

  • The stack expects the built-in LoadBalancer (kiac-lb on both kubeadm and k3s). With --no-lb the Grafana Service never gets an EXTERNAL-IP and the install step fails (the cluster itself keeps working).
  • Grafana shares its node IP with the Traefik gateway when both addons are on: kiac-lb shares an IP whenever port sets are disjoint, and 3000 vs 80/443 do not overlap, so one worker IP is enough for both.
  • The Grafana pod is pinned to the kiac.io/lb-primary node, so the printed URL always delivers traffic to the pod locally instead of crossing vmnet's slow forwarded path. See Networking.
  • Storage is emptyDir with 6h retention: metrics restart from zero when the Prometheus pod does. Right-sized for a laptop, not for keeping history.
  • If an install step fails, kiac logs it and keeps the cluster; the observability stack degrades, the cluster does not tear down.
  • Enable via config file instead of the flag: addons.observability: true. See Config file.
