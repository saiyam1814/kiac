Hands-on

Integration labs

Repeatable workflows that exercise real traffic, storage, APIs, and failure paths on kiac clusters. Each lab includes verification and cleanup instead of stopping at installation.

Run Portainer CE on kiac

Portainer Community EditionOptional Kubernetes management UI; no key required
Open the full guide

Portainer runs as an optional application inside the kiac Kubernetes cluster; it is not built into kiac. The installation example was freshly rerun end to end with kiac v0.5.0. It pins Portainer CE 2.39.5 and chart 239.5.0, binds persistent storage, receives a real LoadBalancer IP, authenticates through the Portainer API, registers the kiac cluster, and reads Kubernetes nodes through Portainer's API proxy.

No license key is needed This installs Portainer Community Edition. Portainer Business Edition is a separate product and does require a license key.
./examples/portainer.sh up
./examples/portainer.sh verify
./examples/portainer.sh cleanup
Run Portainer on kiacInstallation script

Portainer manages the Kubernetes cluster; it does not provide Docker Engine or Docker Compose compatibility for the macOS host.

Run Rancher on kiac

Rancher ManagerOptional Kubernetes management platform; no key required
Open the full guide

Rancher runs as an optional application on a dedicated kiac Kubernetes cluster; it is not built into kiac. The tested example pins Rancher and its stable chart to 2.14.3 on Kubernetes 1.34, uses kiac's Gateway API for HTTPS, authenticates through Rancher's API, and confirms that the local cluster is active with its node visible.

No license key and no extra certificate controller This runs open-source Rancher Manager. A generated TLS secret lets the existing kiac Traefik Gateway terminate HTTPS without installing cert-manager.
./examples/rancher.sh up
./examples/rancher.sh verify
./examples/rancher.sh cleanup
Run Rancher on kiacInstallation script

The script uses a dedicated cluster because Rancher creates cluster-wide controllers, roles, webhooks, custom resources, and system namespaces. Cleanup deletes that owned cluster instead of attempting a partial uninstall from an unrelated environment.

Real Apple GPU and inference

Create a multi-node krunkit-backed cluster, prove that Vulkan names the real Venus device, allocate GPU memory through Kubernetes DRA, run a pinned TinyLlama inference server behind a LoadBalancer, and compare its llama.cpp throughput with native Metal. The lab also exercises namespace-scoped compatibility for legacy nvidia.com/gpu manifests without claiming CUDA support.

Alpha and explicitly not CUDA The pod API is Mesa Venus/Vulkan. CUDA, NVML, nvidia-smi, Metal, and MLX are unavailable inside the Linux guest.
kiac gpu doctor
kiac create cluster --config examples/gpu-cluster.yaml
kubectl apply -f examples/gpu-vulkan.yaml
kiac gpu bench --name gpu-lab
