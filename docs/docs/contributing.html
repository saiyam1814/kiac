Contributing

kiac is a young project and PRs land fast. Issues are scoped with context and acceptance criteria so you can pick one up cold.

Find something to work on

  • Browse the open issues; anything unassigned is up for grabs.
  • New to the codebase? Filter by the good first issue label.
  • Have an idea that is not filed yet? Open an issue first for anything non-trivial, so the approach is agreed before the code exists.

Dev setup

git clone https://github.com/saiyam1814/kiac
cd kiac
make build          # builds bin/kiac with the version stamped in
make test           # go test ./...
make lint           # go vet ./...
make ci             # exact formatting, generation, race, vet, and build gate
./bin/kiac doctor

You need Go, plus the same runtime requirements as any user (Apple silicon, apple/container 1.0+). Unit tests run anywhere; actually creating clusters needs the real runtime.

Project layout

PathWhat lives there
cmd/cobra commands; deliberately thin shims over pkg/cluster
pkg/cluster/cluster lifecycle: create, delete, addons, chaos, diagnostics, kubeconfig, status
pkg/cluster/assets/embedded manifests (metrics-server, observability, gateway, k3s kindnet), versions pinned
pkg/runtime/wrapper around the apple/container CLI
pkg/webui/the local dashboard: Go handlers + one embedded HTML file
kernel/the full node kernel: kconfig fragment; built by the kernel-build CI workflow
test/e2e/trusted Apple silicon runtime tests for multi-node traffic, addons, security boundaries, and restart recovery
docs/this website (GitHub Pages serves the docs/ directory)
examples/example configs like cluster.yaml

What a good PR looks like

  • Unit tests for new behavior (make test passes; CI runs it too).
  • Run make ci before pushing. Runtime-sensitive changes should also run ./test/e2e/run.sh kubeadm or k3s on Apple silicon.
  • Pinned versions for anything new that gets embedded: manifests in pkg/cluster/assets/ pin exact image tags, and node images pin digests.
  • Honest UX on failure: optional addons degrade the cluster rather than tearing it down, errors say what to do next. Keep that bar.
  • Docs updated when flags or behavior change (this site plus the README).
